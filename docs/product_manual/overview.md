# 认识 Uni-Lab OS

## 产品解决什么问题

实验室自动化不只是“让设备动起来”。一次可重复、可追踪的实验还需要知道材料在哪里、设备能执行什么动作、多个任务如何共享工位、异常后是否可以继续，以及最终结果来自哪次执行。

Uni-Lab OS 将这些信息组织为一条闭环：

1. **建立资源事实**：用模板、物料实例、试剂身份、库存和库位描述实验开始前的真实状态。
2. **编排实验步骤**：把设备动作、条件、循环、人工确认和子操作组合成实验操作或工作流。
3. **发布稳定版本**：发布后形成不可变合同；任务引用发布时的修订，不会随之后的编辑漂移。
4. **运行前检查**：预检输入、设备、物料来源、试剂数量、站点唯一性和资源可用性。
5. **调度和执行**：任务冻结执行图，调度器按设备、物料和工位锁安排节点，Edge 向设备下发动作。
6. **观察与恢复**：控制台展示节点状态、反馈、返回值和 Trace；需要时由操作员确认、结算或恢复。

## 产品由哪些部分组成

| 组成 | 面向用户的作用 | 当前环境 |
| --- | --- | --- |
| **Console** | 资源、试剂、实验操作、工作流和任务的日常操作入口。 | `:30183/console/`，<span class="status status-ready">当前可用</span> |
| **Workspace Backend + Scheduler** | 保存定义和运行状态，执行预检、库存预留、任务计划与并行调度。 | `unilabos-local-debug`，<span class="status status-ready">当前可用</span> |
| **Edge Runtime** | 加载设备包，把 Job 转为真实设备动作，并返回反馈和结果。 | `unilabos-local-edge`，10 个在线节点 |
| **SZLab 设备包** | 定义 SZLab 设备、动作、资源、布局和工作流。 | 当前运行时加载 23 个已发布工作流 |
| **PLC-Sim** | 在没有真实 PLC 时模拟 OPC UA 命令、状态、超时和异常。 | [Web GUI `:30160`](http://115.190.137.109:30160/)，<span class="status status-ready">当前可用</span>；不是调度或库存权威 |
| **SigNoZ** | 按任务 Trace 查看 Scheduler 与 Edge 的跨进程执行链路。 | `:30151`，<span class="status status-ready">当前可用</span> |

:::{note}
“逻辑库存占用”来自 Uni-Lab OS 的物料台账，不等同于传感器对现场物体的实时证明。涉及机械臂、开盖、投料等物理动作时，现场传感器、设备控制器、急停和安全联锁始终具有更高优先级。
:::

## 核心对象

**资源模板**
: 定义一类容器、仓库或材料可以有哪些字段、容量、站点和展示模型。

**物料**
: 某个真实容器或样品的实例，具有 UUID、条码、父子关系、当前位置和修订号。

**试剂身份与库存**
: 身份描述“是什么化学品”；库存描述“哪一个容器中有多少、放在哪里”。两者分开管理。

**实验操作**
: 可复用的局部工艺。它也可以发布为合同，被更大的工作流作为一个子节点调用。

**工作流**
: 面向一次实验目标的可发布流程，包含输入、输出、节点、依赖和资源要求。

**任务与 Job**
: 任务是一次工作流运行；Job 是调度器派给某台设备执行的具体节点动作。

**资源锁与库存预留**
: 资源锁防止两个任务同时占用同一设备、物料或工位；库存预留防止同一份试剂被重复承诺。

## 适用角色

- **实验操作员**准备物料和试剂、运行已发布工作流、观察进度和处理人工确认。
- **流程工程师**编排实验操作、导入工作流、维护输入输出合同并在开发模式中单步验证。
- **实验室管理员**维护设备包、连接和运行模式，处理资源锁、未知执行结果、Trace 和部署问题。

## 当前环境的事实快照

截至 2026-09-07，目标环境的 Readiness 为 `ready`，工作流运行时加载 `23/23`，Edge 已连接并报告 10 个在线节点。启动模式为 `develop`；如果要验证两个任务并行仲裁，需要在没有运行中任务和其他阻塞项时切换为 `product`。
