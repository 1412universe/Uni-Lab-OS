# 实验室操作

实验室操作是可复用的局部工艺，例如“标准物料转运”“开盖后移液”或“一次搅拌”。它可以独立维护、发布为不可变合同，再被完整工作流作为一个子节点引用。

## 什么时候使用

当多个工作流需要重复同一段动作、参数和资源语义时，优先把它做成实验操作。这样可以：

- 统一设备绑定和必填参数；
- 明确输入、输出和 `ResourceSlot`；
- 独立发布版本；
- 在上层工作流中复用，而不复制整段节点。

## 创建或导入

进入“实验室操作”页后，可以：

- 在画布中创建新的实验操作；
- 导入 Uni-Lab Python 工作流定义；
- 导入 JSON 定义；
- 打开已有操作查看、编辑、发布或删除。

导入后不要直接假定可运行。先核对节点、连线、设备绑定、公开合同和资源来源，再保存。

## 在画布中编排

### 添加设备动作

1. 从设备与动作目录选择动作模板。
2. 将动作加入画布。
3. 绑定当前实验室中的设备实例。
4. 为每个参数选择来源：

   - 固定值；
   - 工作流公开输入；
   - 上游节点输出；
   - 物料或站点资源来源。

5. 核对参数类型、是否必填和设备动作返回合同。

### 添加控制节点

编辑器支持：

- 条件分支；
- 循环与 `RepeatUntil`；
- 已发布子操作。

人工确认不是独立的 Python 控制节点。编辑器会把一个已绑定的真实设备动作包装为 `manual_confirm`：Scheduler 取得该动作资源后等待批准，批准才下发同一个 Job。必须设置合理超时，允许范围为 1 到 86400 秒；超时不是自动批准，拒绝或超时会取消 Task。详见[人工确认](workflow-features.md#人工确认)。

### 定义输入输出合同

公开合同决定上层工作流和运行准备页能看到什么。应为每个字段填写稳定名称、类型、是否必填和说明，并注意：

- 输入/输出名称不能重复；
- 上游输出类型必须能赋给下游输入；
- `ResourceSlot` 应描述允许的资源模板或站点约束；
- 删除或改名会影响引用该合同的上层流程。

### 引用子操作

只有已发布的实验操作可以作为子工作流插入。每次引用需要分别配置：

- 该次调用的公开参数；
- 设备实例绑定；
- 输入输出连接；
- 资源来源。

上层流程保存的是发布合同的引用。子操作之后发布新版本不会静默改写已经冻结的任务。

## 保存与发布

保存前，Console 会检查名称、节点、连线、设备绑定、必填参数、控制结构、合同唯一性和类型一致性。新建父定义后，如果子节点或连线保存失败，客户端会尝试回滚刚创建的父对象。

发布会把当前修订固化为可引用合同。发布后的操作再次编辑时进入新的源修订，必须重新发布，运行侧才会看到新版本。

:::{warning}
发布不是安全审批，也不证明真机已经验收。它只保证运行时引用的是一个稳定定义。涉及设备或配方变更时，仍需完成相应的测试、现场核对和审批。
:::

## 删除前检查

删除实验操作前，确认没有已发布工作流仍引用它。即使界面允许删除源定义，历史任务仍会保留自己的冻结快照；但之后重新编辑或发布上层流程可能因合同缺失而失败。

## SZLab 示例：标准物料转运

当前环境中的“SZLab 标准物料转运”是一个 `experiment_operation`。它接收资源、源/目标仓库、设备和站点，在标准取放成功后由 Host 唯一一次提交物料归属。SZLab 的多个上层流程复用该合同，以避免在不同工作流中复制转运和记账语义。
